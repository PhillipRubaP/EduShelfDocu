\section{Das Dashboard}

Die Startseite der Anwendung, realisiert in der Komponente \texttt{MainDashboard.jsx}, stellt nach erfolgreicher Authentifizierung die primäre Ansicht für den Benutzer dar. Sie verfolgt das Ziel auf einen Blick die relevantesten Informationen und die häufigsten Aktionen darzustellen. Das Dashboard bündelt Schnellaktionen, kürzlich hinzugefügte Dateien sowie aussagekräftige Statistiken.

\subsection{Architektur und Datenladen}

Ein zentraler Vorteil der beim Dashboard verwendeten Architektur ist das parallele Laden aller benötigten Daten. Anstatt Dokumente, Quizzes und Lernkarten sequenziell abzurufen -- was die Ladezeit mit jeder weiteren Anfrage erhöhen würde -- wird \texttt{Promise.all()} eingesetzt. Diese Methode startet alle asynchronen Anfragen gleichzeitig und wartet, bis die Letzte von ihnen abgeschlossen ist.
\newline

\begin{lstlisting}[language=JavaScript, caption={Paralleles Datenladen mit Promise.all im Dashboard}]
const fetchData = async () => {
  try {
    const [docsData, quizzes, flashcards] = await Promise.all([
      getDocuments(),
      getQuizzes(),
      getFlashcards()
    ]);
    // Alle Daten sind gleichzeitig verfuegbar
    setStats({
      documents: docsData.totalCount || docs.length,
      quizzes:   quizzes.totalCount   || quizzes.length,
      flashcards: flashcards.totalCount || flashcards.length
    });
  } catch (error) {
    console.error('Error fetching dashboard data:', error);
  }
};
\end{lstlisting}

Das Ergebnis ist eine messbar kürzere Wartezeit im Vergleich zu sequenziellen Aufrufen, da die Gesamtdauer der Zeit der langsamsten Einzelanfrage entspricht, nicht der Summe aller Anfragen.

\subsection{Schnellaktionen und Statistik-Widget}

Gegliedert ist das Dashboard in drei Bereiche:

\begin{enumerate}
    \item \textbf{Recently Added}: Zeigt die drei zuletzt hochgeladenen Dokumente mit Name, Typ und zugewiesenen Tags an. Ein Klick öffnet die Datei-Vorschau über \texttt{FileViewer}.
    \item \textbf{Study Stats}: Zeigt die Anzahl von Dokumenten, Quizzes und Lernkarten. Diese Statistiken werden bei jeder Aktion (Upload, Erstellen, Löschen) durch erneuten Aufruf von \texttt{fetchData()} aktualisiert.
    \item \textbf{Quick Actions}: Die drei Schnellaktionen-Schaltflächen ermöglichen das unmittelbare Erstellen eines Uploads, eines Quiz oder einer Lernkarte, ohne dass dafür die entsprechende Unterseite aufgerufen werden muss. Die zugehörigen Modals werden direkt gerendert und angezeigt.
\end{enumerate}

Dieses Konzept minimiert die Anzahl der notwendigen Navigationsschritte für häufig ausgeführte Aktionen und entspricht der Zielsetzung einer effizienten Lernoberfläche.
