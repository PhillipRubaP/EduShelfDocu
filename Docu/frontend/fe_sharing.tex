\section{Datei-Sharing zwischen Nutzern}

Eine weitere wesentliche Funktion von EduShelf ist die Möglichkeit, Dokumente mit anderen Nutzern zu teilen. Der komplette Sharing-Prozess wird durch die Komponente \texttt{ShareFileModal.jsx} in Verbindung mit der Dateiansicht \texttt{Files.jsx} realisiert.

    \centering

\subsection{Share-Dialog (ShareFileModal.jsx)}

Der Share-Dialog ist als Pop-Up-Modal implementiert. Der Nutzer gibt die E-Mail-Adresse oder den Benutzernamen der Zielperson ein. Da beide Eingabeformate akzeptiert werden, entfällt die Notwendigkeit, die genaue Identifikation des Empfängers zu kennen -- das Backend löst die Zuordnung auf.

\begin{lstlisting}[language=JavaScript, caption={Formularlogik im ShareFileModal}]
const ShareFileModal = ({ isOpen, onClose, onShare, fileName }) => {
    const [emailOrUsername, setEmailOrUsername] = useState('');
    const [isLoading, setIsLoading] = useState(false);

    const handleSubmit = async (e) => {
        e.preventDefault();
        if (!emailOrUsername.trim()) return;

        setIsLoading(true);
        try {
            await onShare(emailOrUsername); // Callback an Files.jsx
            setEmailOrUsername('');         // Eingabe nach Erfolg zuruecksetzen
        } finally {
            setIsLoading(false);
        }
    };
};
\end{lstlisting}

Während des Sendevorgangs wird der Submit-Button deaktiviert (\texttt{disabled={isLoading}}) und der Text wechselt von \textit{Share File} zu \textit{Sharing...}. Dieses Muster verhindert mehrere Einreichungen und gibt dem Nutzer visuelles Feedback über den schon laufenden Prozess.


\subsection{Zustandsverwaltung für Shared Files}

Empfangene Freigaben werden im Dateibereich des Empfängers mit einem visuellen Attribut (\texttt{isShared: true}) angezeigt, um klarzumachen, dass es kein eigenes File ist. Der Nutzer hat die Möglichkeit, eine Freigabe zu akzeptieren oder abzulehnen. Diese Entscheidung wird anschließend serverseitig gespeichert, sodass der Status geräteübergreifend abrufbar bleibt:

\begin{lstlisting}[language=JavaScript, caption={Serverseitige Speicherung der Shares via API}]
// Akzeptieren einer Freigabe
const handleAcceptShare = async (docId) => {
    await api.patch(`/files/shared/${docId}/accept`);
    fetchFiles(); // Listenaktualisierung ausloesen
};

// Ablehnen einer Freigabe
const handleRejectShare = async (docId) => {
    await api.patch(`/files/shared/${docId}/reject`);
    fetchFiles();
};
\end{lstlisting}

\subsection{Bewertung des Ansatzes}

Die Entscheidung, den Accept/Reject-Status serverseitig zu speichern, stellt sicher, dass der Share-Status geräteübergreifend verfügbar ist. Akzeptiert ein Nutzer eine Freigabe auf einem Gerät, ist diese Entscheidung auch auf allen anderen Geräten, die mit diesem Account eingeloogt sind, sofort sichtbar. Dadurch entfallen die früheren Einschränkungen einer rein clientseitigen Lösung und die User Expierience erhöht sich deutlich. Die API-Aufrufe erfolgen asynchron, sodass die Benutzeroberfläche mit den aktuellen Daten vom Server aktualisiert wird.
