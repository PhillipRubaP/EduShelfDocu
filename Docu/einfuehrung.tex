\chapter{Einführung}

\section{Motivation}

Der Umgang mit Lernmaterialien im Bildungsalltag ist trotz fortschreitender Digitalisierung nach wie vor nicht optimal: Dokumente liegen in verschiedenen Cloud-Diensten und Ordnern verstreut, Zusammenfassungen werden manuell erstellt und das gezielte Heraussuchen von Informationen aus umfangreichen Skripten oder Büchern kostet wertvolle Zeit. Gleichzeitig haben LLMs (Large Language Models) in den letzten Jahren ein Level erreicht, welches eine sinnvolle Integration in produktive Anwendungen ermöglicht -- ohne dabei auf kommerzielle Drittanbieter-APIs angewiesen zu sein, die den Datenschutz gefährden könnten.

\textbf{EduShelf} adressiert genau diese Lücke: Die Plattform kombiniert zentrales Dokumentenmanagement mit KI-gestütztem Lernen in einer einzigen, datenschutzfreundlichen Webanwendung. Nutzerinnen und Nutzer können ihre Unterlagen hochladen und anschließend direkt damit interagieren -- durch gezielte Fragen, automatische Lernkarten oder Multiple-Choice-Quizzes, die das LLM inklusive RAG-System aus dem Dokumenteninhalt generiert.

\section{Umfeld und Stand der Technik}

\subsection{Existierende Lösungen und ihre Grenzen}

Auf dem Markt existieren bereits Teillösungen des Problems:

\begin{itemize}
    \item \textbf{Cloud-Speicherdienste} (z.B. Google Drive, OneDrive) ermöglichen das Ablegen und Teilen von Dokumenten, bieten aber keine inhaltliche Interaktion mit den Dateien.
    \item \textbf{KI-Chatbots} (z.B. ChatGPT, Google Gemini) können Fragen beantworten, haben jedoch keinen Zugriff auf eigene, private Dokumente (müssen pro Chat hochgeladen werden) -- oder senden diese zur Verarbeitung an externe Server, was datenschutztechnisch problematisch ist.
    \item \textbf{Lernkarten-Apps} (z.B. Anki) müssen meist manuell befüllt werden und sind nicht an eine Dokumentbibliothek angebunden.
\end{itemize}

Eine Plattform, die Dokumentenverwaltung, Suche und KI-Lernhilfen in einem lokalen, datenschutzkonformen System vereint, existierte bisher nicht als Open-Source-Lösung für den Bildungsbereich.

\subsection{Retrieval-Augmented Generation (RAG)}

Der zentrale technische Ansatz von EduShelf ist \textit{Retrieval-Augmented Generation} (RAG). Dabei wird ein LLM nicht mit seinem statischen Trainingswissen allein befragt, sondern mit relevantem Kontext aus einem externen Wissensspeicher angereichert. Konkret bedeutet das:

\begin{enumerate}
    \item Hochgeladene Dokumente werden in kleine Textabschnitte (\textit{Chunks}) zerlegt und als Vektoren in einer Datenbank gespeichert.
    \item Bei einer Nutzeranfrage werden die semantisch passendsten Chunks per Vektorsuche abgerufen.
    \item Diese Chunks werden als Kontext zusammen mit der Frage an das LLM übergeben.
    \item Das LLM generiert eine passende, auf das Dokument bezogene Antwort.
\end{enumerate}

Dieses Verfahren reduziert Halluzinationen und ermöglicht es, ein lokal betriebenes Modell (ohne Internetzugang) mit dokumentenspezifischem Wissen zu versorgen.

\section{Aufgabenstellung}

Im Rahmen dieser Diplomarbeit an der HTL Hollabrunn wurde die Plattform \textbf{EduShelf} vollständig konzipiert, implementiert und dokumentiert. Das System besteht aus drei Hauptkomponenten, die in jeweils 2 Arbeitsbereiche aufgeteilt wurden:

\begin{itemize}
    \item \textbf{Web-Frontend} (Elias Welt): Eine React-basierte Single-Page-Application mit vollständiger Benutzeroberfläche für Dokumentverwaltung, Chat, Lernkarten und Quizze.
    \item \textbf{Backend-API} (Phillip Rubak): Eine ASP.NET Core 8 Web API, die als zentrale Schnittstelle zwischen Frontend, Datenbank, KI-Modell und Dateispeicher fungiert.
\end{itemize}

\subsection{Funktionale Anforderungen}

Das System soll folgende Kernfunktionen bereitstellen:

\begin{enumerate}
    \item \textbf{Benutzerverwaltung:} Registrierung mit E-Mail-Verifizierung, Login, rollenbasierte Zugriffskontrolle (Student / Admin).
    \item \textbf{Dokumentenverwaltung:} Upload, Ansicht, Herunterladen und Löschen von Dokumenten verschiedener Formate (PDF, DOCX, TXT). Dokumente können mit anderen Nutzern geteilt werden.
    \item \textbf{KI-Chatbot (RAG):} Nutzer können Fragen zu ihren Dokumenten stellen. Das System erkennt die Nutzerintention automatisch und ruft relevante Dokumentenabschnitte ab.
    \item \textbf{Lernkarten-Generierung:} Aus Dokumenteninhalten werden automatisch Flashcards (Frage-Antwort-Paare) generiert, die in einem interaktiven Review-Modus geübt werden können.
    \item \textbf{Quiz-Generierung:} Das System erstellt automatisch Multiple-Choice-Quizze aus hochgeladenen Dokumenten, inklusive Auswertung und Ergebnisanzeige.
    \item \textbf{Tag-System:} Dokumente und Lernkarten können mit Tags versehen und gefiltert werden.
\end{enumerate}

\subsection{Nicht-funktionale Anforderungen}

\begin{itemize}
    \item \textbf{Datenschutz:} Alle KI-Operationen laufen lokal auf dem Server (via Ollama). Es werden keine Dokumenteninhalte an externe Dienste übertragen.
    \item \textbf{Deployment:} Das gesamte System ist containerisiert (Docker Compose) und auf einem einzelnen Linux-Server betreibbar.
    \item \textbf{Erweiterbarkeit:} Die Architektur ist modular aufgebaut, sodass neue KI-Modelle oder Features ohne Umbau des Gesamtsystems integriert werden können.
    \item \textbf{Sicherheit:} Passwörter werden mit BCrypt gehasht, Sessions über HttpOnly-Cookies verwaltet, und alle API-Endpunkte sind standardmäßig durch Authentifizierung geschützt.
\end{itemize}

\section{Aufbau der Arbeit}

Die vorliegende Diplomarbeit ist in zwei Hauptteile gegliedert:

\begin{itemize}
    \item \textbf{Frontend-Dokumentation} beschreibt die React-Architektur, das Komponentendesign, das Routing, die API-Anbindung und das UX-Design der Webanwendung (Elias Welt).
    \item \textbf{Backend-Dokumentation} beschreibt die Systemarchitektur, das Datenmodell, die REST-API, die RAG-Pipeline, die KI-Dienste, die Infrastruktur sowie die Qualitätssicherung durch automatisierte Tests (Phillip Rubak).
\end{itemize}
